# План виправлення проблем з інтерактивними об'єктами

## Пріоритети

### 🔴 Пріоритет 1: Критичні проблеми (зараз)

#### 1.1 Світильники (CogitoSwitch) не працюють
**Проблема:** Світильники не синхронізуються між клієнтами.

**Аналіз:**
- `NetworkInteractable` вже підтримує `CogitoSwitch`
- Сигнал `switched(is_on: bool)` вже підключений
- Проблема може бути в тому, що:
  - Сигнал не спрацьовує на хості
  - Стан не синхронізується правильно
  - Клієнти не отримують RPC

**План виправлення:**
1. Додати діагностичні логи для `_on_switch_state_changed`
2. Перевірити, чи правильно спрацьовує сигнал `switched` на хості
3. Перевірити, чи правильно синхронізується стан `is_on`
4. Перевірити, чи клієнти отримують RPC і застосовують стан

**Оцінка:** 30-60 хвилин

---

#### 1.2 Скриня (CogitoContainer) - предмети не синхронізуються
**Проблема:** Коли гравець забирає предмет зі скрині, предмети лишаються в іншого гравця.

**Аналіз:**
- `CogitoContainer` не підтримується `NetworkInteractable`
- Інвентар скрині (`inventory_data`) не синхронізується між клієнтами
- Потрібно синхронізувати:
  - Відкриття/закриття скрині (анімація)
  - Зміни в інвентарі скрині (додавання/видалення предметів)

**План виправлення:**
1. Додати підтримку `CogitoContainer` в `NetworkInteractable`
2. Синхронізувати стан відкриття/закриття (через сигнали `toggle_inventory`, `container_closed`)
3. Синхронізувати інвентар скрині:
   - Підключитися до сигналів інвентаря скрині (якщо вони є)
   - Або синхронізувати через `NetworkInventorySync` (якщо він підтримує контейнери)
   - Або створити окремий компонент `NetworkContainerSync`

**Оцінка:** 2-4 години

---

### 🟡 Пріоритет 2: Важливі проблеми (потім)

#### 2.1 Анімації обертання (CogitoTurnwheel)
**Проблема:** Штука яку треба прокрутити не крутиться в іншого клієнта.

**Аналіз:**
- `CogitoTurnwheel` не підтримується `NetworkInteractable`
- Потрібно синхронізувати:
  - Стан `has_been_turned` (bool)
  - Поточний кут обертання (float) - для плавної синхронізації
  - Анімацію обертання під час взаємодії

**План виправлення:**
1. Додати підтримку `CogitoTurnwheel` в `NetworkInteractable`
2. Синхронізувати стан `has_been_turned` (один раз після завершення взаємодії)
3. Опціонально: синхронізувати кут обертання під час взаємодії (для плавності)

**Оцінка:** 1-2 години

---

#### 2.2 Інші анімації під час інтеракцій
**Проблема:** Деякі анімації не синхронізуються між клієнтами.

**Аналіз:**
- Анімації можуть бути в різних об'єктах:
  - `CogitoDoor` - вже працює (через стан відкрито/закрито)
  - `CogitoContainer` - потрібно додати (через стан відкрито/закрито)
  - `CogitoSwitch` - може мати анімації (через стан вкл/викл)
  - `CogitoTurnwheel` - потрібно додати (через стан обертання)
  - Інші об'єкти з анімаціями

**План виправлення:**
1. Перевірити, які об'єкти мають анімації
2. Додати синхронізацію анімацій для кожного типу об'єкта
3. Використовувати події (signals) для синхронізації анімацій, а не постійний стімінг

**Оцінка:** 2-3 години (залежить від кількості об'єктів)

---

## Загальний підхід

### Архітектура синхронізації

1. **Подійна синхронізація (Event-based):**
   - Використовувати сигнали об'єктів для виявлення змін
   - Синхронізувати тільки при зміні стану (не постійно)
   - Хост відправляє RPC при зміні, клієнти застосовують зміни

2. **Типи синхронізації:**
   - **Булеві стани** (is_open, is_on, has_been_turned) - простий RPC
   - **Інвентарі** (контейнери) - синхронізація через `NetworkInventorySync` або окремий компонент
   - **Анімації** - синхронізація через стан (відкрито/закрито, вкл/викл) або через події

3. **Компоненти:**
   - `NetworkInteractable` - для базових інтерактивних об'єктів (двері, вимикачі)
   - `NetworkContainerSync` (можливо) - для контейнерів з інвентарем
   - Розширення `NetworkInteractable` для нових типів об'єктів

## Примітки

- Всі зміни мають бути зворотно сумісними
- Використовувати подійну синхронізацію (не постійний стімінг)
- Додавати діагностичні логи для дебагу
- Тестувати на двох клієнтах (хост + клієнт)
